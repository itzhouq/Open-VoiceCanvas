# VoiceWove GEO 审计：用户问题与网站优化清单

审计日期：2026-11-10（Asia/Shanghai）\
对象：[voicewove.com](https://voicewove.com)，本地仓库 Open-VoiceCanvas\
源码基线：`a39e31b328daae0f7e7f58444b9b320f7e65ad18`\
范围：当前公开页面、相关源码、已有 GSC 数据与官方搜索文档；本次交付为分析与优化建议。

## 1. 结论与证据边界

VoiceWove 已有四个可抓取的功能落地页、FAQ、基础结构化数据、站点地图和内部链接。GEO 的首要工作是让这些页面成为可信的产品答案来源，尤其是多角色故事配音、可选声音的播客、自己的声音克隆，以及按量购买等场景。

当前最需要先解决的是事实不一致：免费额度、字符包数量、克隆收费、商用规则、下载格式和语言数量。继续扩大内容之前，应先保证用户、搜索引擎与 AI 读取到的是同一套准确事实。

本报告使用三类证据：

- **线上确认**：2026-11-10 获取首页、价格页、四个功能落地页、条款和隐私页面，8 个页面均返回 HTTP 200，读取初始 HTML 的可见文本与 JSON-LD。另核对 robots、sitemap、llms 文件与部分应用/账户路由。
- **源码确认**：产品默认配额、支付发放规则、输出格式、页面标题与语言切换等代码。源码行为不等于已验证的生产账户权益或端到端合成结果。
- **历史需求信号**：仓库中 GSC 导出的窗口为 **2026-10-01 至 2026-10-26**，有 160 条查询记录。它不是当前流量数据，也不是 AI 对话记录。

没有进行生产付费、创建克隆、生成音频、读取生产密钥或修改线上配置；没有开展 ChatGPT、Perplexity 等平台的实际回答抽样。因此，下面的问题是有产品和搜索线索支持的候选问题，不能称为已测得的 AI 高频问题，也不能报告当前 AI 引用率。

## 3. P0：先统一会影响购买和信任的事实

P0 表示内容准确性与购买风险优先级，不表示网站存在已验证的宕机。

| 问题 | 证据与边界 | 应做的优化 | 验收标准 |
|---|---|---|---|
| 免费额度有两套答案 | 线上首页和 `/pricing` 为 1,000；四个落地页为 10,000。后端默认 10,000，但允许环境变量覆盖 | 确认当前线上试用权益，统一页面、翻译、metadata、FAQ、JSON-LD 和摘要 | 用一个合规测试账号或只读配置/权益核对确认实际值；公开内容全部一致 |
| $6 字符包存在十倍差异 | 线上价格页显示 `100K characters`；当前 Creem 发放配置为 10,000 字符。未验证当前生产支付商品与真实订单发放 | 核实商品、价格、权益后纠正文案或业务配置；优先避免用户据错误信息购买 | 商品配置、结账说明、发放逻辑、价格页与各语言描述一致 |

## 4. P1：把现有页面补成能支持决策的答案

| 页面 | 应新增或补强的内容 | 需要先核实的事实 |
|---|---|---|
| `/ai-story-voiceover` | 多角色配音流程；旁白+两个角色的完整样例；角色分配与修改；长文本分段；输出规格；用量和商用说明 | 当前整段下载代码为 WAV，不能继续笼统承诺 MP3；角色修改与分段重生成需实际验证 |
| `/ai-podcast-generator` | 输入主题/文章的区别；脚本如何修改；主持人声音选择；双人对话示例；下载和发布流程 | “粘贴文档文字”不等于直接解析 PDF/Word；完整音轨合并代码为 WAV |
| `/voice-cloning` | 免费与付费边界；录音时长/大小/格式；好坏样本对照；跨语言样音；克隆后怎么使用；授权和删除说明 | 样本要求以当前接口与供应商为准；不能用本站记录删除直接保证供应商模型已删除 |
| `/free-text-to-speech` | 注册和试用条件；字符计数示例；输入格式；TTS 实际输出格式；可试听样音；如何选择声音 | TTS 文件处理代码支持 txt/md，对 PDF/Word 明确返回暂不支持；支持范围应分功能说明 |
| `/pricing` | 试用、月付、年付、字符包、克隆次数对照；偶尔使用与持续使用的示例；到期、取消、失败扣费与退款 | 单位应明确为字符，不能混为英文单词或音频分钟；估算时长需公开语速假设 |
| `/privacy`、`/terms` | 商用矩阵；本人/授权声音要求；实际处理服务商；录音、模型、历史记录的保留与删除范围 | 供应商授权、删除和训练政策属于核验任务，不能从一般隐私模板推断 |

内容组织建议：

1. **开头直接回答主要问题。** 说明适合谁、能完成什么、关键限制是什么。每段围绕一个明确问题，字数以讲清楚为准。
2. **提供真实示例。** 音频旁边放脚本、角色标签、语言、输出格式、使用设置和生成日期。若经过后期处理，应说明。
3. **给出操作步骤与规格表。** 明确输入、输出、需要登录/付费的步骤、失败时如何处理。
4. **回答购买前的问题。** 价格、额度、商用、隐私、限制应能在公开页面读到，不依赖注册后问客服。
5. **链接到事实负责页面。** 费用归价格页、授权归条款、数据处理归隐私；场景页提供简短说明和明确链接。

例如，故事页可以用以下内容骨架，方括号内容在核验前不能直接上线：

> **怎样让一篇故事中的不同角色使用不同声音？**\
> VoiceWove 的故事工具支持给旁白和角色选择声音，再生成故事音频。下面用一段包含旁白和两个人物的脚本演示完整流程，并说明角色识别需要检查的地方。整段音轨的下载格式为［经实际导出确认的格式］，生成消耗［经核验的字符计费规则］。

已有 FAQ 和 Schema 可复用；不需要把页面拆成大量零散问答。样例应让人能判断音质、角色一致性和停顿，而不是只加“自然、专业、最佳”等评价词。

其他应核实的承诺：

- **40+/50+语言、200+音色**：不同页面口径不同。当前界面开放的引擎和预置音色列表，不能直接代表实际可用的所有跨语言能力。应区分“可选择的预置声音”“引擎支持合成的语言”“已经实际验证的语言”。
- **外部 API**：存在内部 `/api/` 路由并不代表提供公开开发者 API。对外承诺前应确认鉴权、配额、文档与支持政策。
- **竞品说法**：“所有 AI 平台克隆都收费”“类似 NotebookLM 的工具不能控制语言或发布输出”等表述没有足够证据，应删改或按当前官方资料与实测结果重写。

| P1 | 原始 HTML 的部分标题出现两次 `\| VoiceWove`；根 `TitleUpdater` 又会无条件设置通用标题 | 由路由统一负责标题，品牌后缀只加一次。验收直接打开与站内跳转后的最终标题均保持当前页面主题。客户端覆盖是源码发现，尚未做浏览器最终 DOM 验证 |
| P1 | `/app`、`/forgot-password` 线上为 index/follow，canonical 指向首页 | 按用途明确是否索引。应用工具若承接搜索需有公开说明和 self-canonical；账户/找回密码等使用 noindex。首页 canonical 不能替代不收录设置 |
| P1 | robots 中 `/app/` 与实际 `/app` 不同；部分账户页被 robots 阻止但 HTML 仍默认 index | 统一抓取和索引策略。需搜索引擎看到 noindex 时不能同时依赖 robots 阻止抓取。robots 不承担鉴权或保护私密内容的作用 |
| P1 | 工具页初始 HTML 有 H1 和一句介绍，但主要交互和详情在 mounted 后输出 | 让能力、规格、限制、步骤在服务端外壳或对应公开落地页可读取，客户端负责操作。不要把现状说成全站无法抓取 |
| P2 | 界面语言切换保存在 localStorage，HTML 固定 en，无独立语言 URL | 根据目标市场挑选少量语言，建立完整翻译 URL、对应 lang/self-canonical/双向 hreflang。仅有英文 URL 时，不应把缺 hreflang 单独判为错误 |
| P2 | app 和 public 同时保存 robots/sitemap；线上当前采用 app 路由版本 | 保留一个有效生成入口，避免以后改错副本。当前没有证据说明双文件导致线上冲突 |
| P2 | sitemap 将所有页面 lastmod 设置为构建时间 | 使用实际内容修改日期；没有可靠日期可省略。不要把每次部署当作所有内容更新 |
| P2 | llms.txt 只列旧工具入口，漏四个公开落地页 | 增加主要场景、价格、授权与帮助入口；内容跟随公开页面维护，作为辅助发现材料 |

已有基础应继续保留：

- 公开落地页初始 HTML 有完整正文、FAQ、自引用 canonical，JSON-LD 可解析。
- 现有 `Organization`、`WebSite`、`SoftwareApplication` 与 `FAQPage` 已提供结构信息。FAQ 正文与结构化数据由同一个数组生成，机制合理，重点是纠正答案。
- sitemap 返回 200，包含 13 个 URL；四个落地页有页脚入口和互链。
- robots 通配规则允许公开页面；本次没有发现已验证的全站抓取阻断。
- 当前 www 会跳转到主域，不能照搬历史报告重新认定仍有重复站点问题。

官方原则：Google 的 AI 搜索展示沿用基础搜索资格，页面须可索引且允许摘要，没有额外技术门槛；可见正文与结构化数据必须一致。OpenAI 官方区分用于搜索的 `OAI-SearchBot` 和用于潜在训练的 `GPTBot`，两者可独立配置。允许搜索抓取不必以允许训练为前提。实际 CDN/WAF 是否误拦真实爬虫，应结合日志及官方 IP 规则核验，仅伪装 User-Agent 返回 200 不能证明。

`llms.txt`、FAQ Schema 或某种答案字数都不能保证被 AI 引用；不把“增加 AI 文件”当作本项目主要增长措施。本次也没有测性能或 Core Web Vitals，不给出未经测量的性能结论。

## 7. 如何评估 GEO 是否有效

分别观察四件事：**AI 是否提到品牌、是否推荐为候选、是否引用本站、是否正确描述产品**。这些指标不能合为“AI 排名”。

建议先用 12 条固定问题做小规模基线，其中包含无品牌需求、场景比较和品牌事实核对；不同平台、国家、语言与是否开启联网分别记录。示例英文问题：

1. How can I give the narrator and each character a different voice in an audio story?
2. What tool can narrate YouTube stories without recording my own voice?
3. How can I turn an article into a two-host podcast and choose both voices?
4. Which text-to-speech tools offer one-time credit packs instead of a subscription?
5. How does VoiceWove compare with ElevenLabs for multi-character story narration?
6. What alternatives to NotebookLM let me choose the speakers' voices?
7. How many free characters does VoiceWove offer, and when do they expire?
8. Does VoiceWove's free trial include creating a cloned voice?
9. How many characters are included in VoiceWove's $6 pack?
10. Can I download a complete VoiceWove story or podcast as MP3 or WAV?
11. Can I use audio generated with VoiceWove commercially?
12. What happens to my recording and voice model when I delete a cloned voice?

每个问题在相同配置下重复 3–5 次，记录次数与样本量。品牌事实题用于纠错监测，不能用它们的高提及率证明无品牌获客改善。多轮对话可追加“需要付多少钱”“能否商用”“支持我的语言吗”，观察产品是否在这些约束下仍被推荐。

建议台账字段：日期、平台/模型或产品界面、联网状态、地区/语言、问题版本、完整回答、是否提及、是否推荐、引用 URL、事实错误、访问及转化。

| 指标 | 定义 | 注意事项 |
|---|---|---|
| 品牌提及率 | 提到 VoiceWove 的有效回答数 / 有效回答数 | 品牌题与非品牌题分开统计 |
| 推荐率 | 将产品列为适用候选的回答数 / 有效回答数 | 被引用不代表被推荐 |
| 本站引用率 | 带本站来源链接的回答数 / 有效回答数 | 同时记录被引用的具体页面 |
| 事实准确率 | 经核实正确的产品事实数 / 已核验产品事实数 | 未知事实单列，不能计作正确 |
| 引流与转化 | 可识别的 AI 来源访问、注册、首次成功生成、付费 | 引用不一定带来点击；来源丢失时不能把所有直接流量算作 AI |

已有 GSC 与行为分析可作为背景数据；Google 的 AI 搜索流量归入 Search Console 的 Web 搜索报告，不能把它直接解释为单独的 AI 引用报告。建议发布后保留一段观察窗口再比较，并固定题库和采样配置；本报告没有创建任何定时任务。
